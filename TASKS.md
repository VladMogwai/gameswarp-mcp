# praxis-mcp — рабочая спека

MCP-сервер, дающий модели исследовать репозиторий: диф, поиск по коду и — главное —
поиск по писаным конвенциям команды.

## Правила игры

- Весь `src/` пишешь ты. Скелет, конфиги, CI, зависимости — не твоя забота.
- Спека ниже описывает **контракт**, а не реализацию. Как именно — решаешь сам.
- Не делай в этом репо: векторный поиск, эмбеддинги, вызовы LLM, БД, HTTP-транспорт.
  Всё это — основной проект. Здесь только stdio и файловая система.

## Прежде чем писать

- Спецификация MCP: https://modelcontextprotocol.io/specification — раздел про
  транспорт stdio, хендшейк `initialize`, методы `tools/list` и `tools/call`.
- TypeScript SDK: https://github.com/modelcontextprotocol/typescript-sdk
- Установлено и проверено: `@modelcontextprotocol/sdk` 1.30, `zod` 4.5 (совместимы).

Точка входа — `src/index.ts`. Пока её нет, `npm run typecheck` ругается
«No inputs were found» — это ожидаемо, не баг скелета.

## Инвариант для всех инструментов

1. **Корень репозитория задаётся при старте** (аргумент CLI). Ни один инструмент
   не должен уметь прочитать что-либо вне этого корня. Проверь `../`, симлинки,
   абсолютные пути.
2. **Потолок вывода.** Реши число (например 20k символов) и держи его. При
   превышении — не молчаливая обрезка, а внятный ответ модели: что урезано и как
   сузить запрос.
3. **Ошибка — это подсказка.** «File not found» бесполезно. «File not found;
   did you mean src/index.ts? use search_code to locate it» — полезно.
4. Никакого вывода в `stdout`, кроме протокола. Логи только в `stderr`.

## День 1 — протокол

### `list_changed_files`

```
in:  base: string (git ref, default "HEAD~1"), head: string (default "HEAD")
out: список путей + статус (added/modified/deleted) + счётчик строк +/-
```

Цель дня — не инструмент, а понимание хендшейка.

**verify:** сервер подключён к Claude Code, `tools/list` его показывает,
вопрос «какие файлы изменились» отрабатывает через вызов инструмента.

## День 2 — чтение и поиск

### `read_file`

```
in:  path: string (относительно корня), start_line?: number, end_line?: number
out: содержимое с номерами строк
```

Обязательно: отказ на бинарники, отказ на выход за корень, потолок размера.
Без номеров строк ревью не сможет сослаться на место — это не косметика.

### `search_code`

```
in:  query: string, glob?: string, max_results?: number
out: путь:строка + сама строка + немного контекста вокруг
```

Решение на подумать: звать системный `ripgrep` (быстро, но внешняя зависимость)
или читать самому (медленнее, зато `npx` работает у всех). Запиши выбор и
причину в README — это ровно тот трейдофф, про который спрашивают на интервью.

**verify:** направил на чужой большой репозиторий, задал вопрос, требующий
3–4 вызовов подряд — модель сама собрала ответ.

## День 3 — конвенции и определения

### `search_conventions` — ядро проекта

```
in:  query: string
out: релевантные секции из документов команды + откуда взяты (файл + заголовок)
```

Где искать: `CONTRIBUTING.md`, `CONVENTIONS.md`, `STYLE*.md`, `docs/**/*.md`,
`**/adr/**/*.md`, `**/architecture-decisions/**`, `.github/*.md`.

Резать markdown по заголовкам на секции и искать по секциям, а не по файлам
целиком — файл на 2000 строк бесполезен как результат.

**Только ключевые слова / BM25. Никаких векторов.** Они в основном проекте.

### `find_definition`

```
in:  symbol: string
out: где объявлен (файл, строка, сама строка объявления)
```

Набор regex-паттернов для TS/JS поверх `search_code`. Парсер не пиши.
Ограничение честно задокументируй в README.

**verify:** на репозитории с внятным CONTRIBUTING вопрос «какое у нас
соглашение по обработке ошибок» возвращает реальную секцию.

## День 4 — то, ради чего всё

### Описания инструментов

Перепиши все `description` набело. Описание — единственное, по чему модель
решает, звать инструмент или нет.

**Эксперимент, который надо провести и записать:** возьми один сценарий,
прогони его с исходным описанием `search_conventions`, потом с переписанным.
Посчитай, сколько раз инструмент был вызван и был ли вызван вообще.
Это данные для поста.

### Публикация

- README: установка, конфиг для Claude Code, транскрипт живой сессии.
- Публичный репозиторий (для публичных репо GitHub Actions бесплатны без лимита).
- npm publish (бесплатно).

**verify:** `npx praxis-mcp /path/to/repo` работает у человека, который ничего
про проект не знает.
